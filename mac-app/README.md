# Blog for Mac M1 · 2.1.0

Windows Blog의 CLI 원고·검수·이미지·네이버 편집기 엔진을 Apple Silicon용으로 묶은 macOS 앱입니다. Mac에서는 **자동화 기본 꺼짐**, **수동 키워드 작성**, **네이버 임시저장 기본값**을 사용합니다. Python을 따로 설치할 필요 없이 ARM64 엔진이 앱에 포함됩니다. 생성에는 API 키 대신 설치된 CLI의 구독 계정을 사용합니다.

## 설치와 사용

`Blog-M1-2.1.0.zip`을 완전히 풀고 `Install-Blog.command`를 Control-클릭 → 열기로 실행합니다. 설치 위치는 `~/Applications/Blog.app`입니다. 자세한 순서는 [MAC-INSTALL.txt](MAC-INSTALL.txt)에 있습니다.

1. 설치된 Codex(ChatGPT), Claude, Antigravity CLI의 연결 상태를 확인합니다. 로그인 버튼으로 열린 Terminal에서 인증한 뒤 다시 연결을 확인합니다. 원고 단계에서 제외한 Claude는 필요하지 않지만, 현재 이미지 생성에는 ChatGPT와 Antigravity가 모두 필요합니다.
2. 네이버 저장·발행을 사용하려면 웨일을 설치하고 앱의 로그인 버튼으로 열린 전용 창에서 한 번 로그인합니다. 로컬 저장에는 네이버 로그인이 필요하지 않습니다.
3. 키워드를 입력하고 작성합니다. 실제 연관 검색어를 수집해 검색 의도를 정하고, 입력한 주제를 유지하면서 원고와 이미지를 준비합니다.
4. 완료 동작을 네이버 임시저장 / 바로 발행 / 로컬 저장 중 선택합니다. 프롬프트 여러 개와 단계별 CLI·역할·모델은 자동 저장됩니다.
5. 반복 실행을 원할 때만 자동화를 켭니다. 첫 회차는 바로 시작하고 완료 후 1~6시간 간격으로 반복합니다. 자동화를 끄면 진행 중 작업도 중지합니다. 실행 중 바꾼 작성 설정은 다음 새 글부터, 간격은 다음 예약부터 적용됩니다.

하단 진행 창은 모든 탭에 표시되며 경계선을 드래그하거나 접을 수 있습니다. 높이도 저장합니다. 기존 검색·이미지·댓글 도구는 보조 탭에 유지됩니다.

## 인증과 복구

- Finder 실행 시 빠지는 Homebrew·사용자 Node 설치 경로를 별도로 탐색합니다. CLI 앱 창을 실행했다고 로그인 성공으로 표시하지 않습니다.
- ChatGPT의 일반 로그인 콜백이 실패하면 계정 연결의 `기기 코드 로그인`을 선택합니다. Terminal 안내에 따라 본인 계정 인증을 마친 뒤 CLI 로그인 재확인을 누릅니다.
- 일반 웨일의 쿠키·암호 파일을 복사하던 방식은 제거했습니다. 새 `naver-whale-profile-v2`를 유지하고 로그인된 보호 페이지까지 확인합니다. 이전 자동화 프로필의 손상된 인증 정보를 다시 가져오지 않습니다.
- ARM64 ChromeDriver는 실제 웨일 버전에 맞추어 내려받고 바이너리·버전·캐시 해시를 확인합니다. 전용 웨일 연결은 로컬 포트 9449를 사용합니다. 편집기는 macOS Command 키와 한국어 시스템 글꼴을 사용합니다.
- 중지·오류 시 `mac-active-run.json`과 회차 자료로 재개합니다. 원고가 이미 준비되었으면 다시 생성하지 않습니다. 제출 영수증과 발행 URL을 먼저 확인하여 결과가 불확실한 글을 자동으로 중복 제출하지 않습니다.
- 편집기 뒤에 늦게 나타나는 기존 원고 복구 창은 해당 글쓰기 탭을 활성화한 뒤 처리합니다. 제출 직전에 원고·사진을 다시 검사하며 최종 발행 버튼을 무조건 재클릭하지 않습니다.
- 표지 한글에 실제 그림자를 적용하고 변경된 표지는 다시 검수합니다. 발행된 네이버 해시태그의 기본 색상은 본문 강조 색상과 구별하며 사용한 연관어도 원고 기록에 보존합니다.
- 2.1.0는 첫 이미지와 Google 캡처의 한글 질문을 굵은 고딕체로 가운데 정렬하고 흰색·형광 녹색·형광 빨간색을 함께 사용합니다. 반투명 검정 배경과 그림자를 적용하며 저장된 구식 앱 프롬프트는 사용자 문장을 보존한 채 최신 규칙으로 자동 갱신합니다.
- 네이버 발행 설정창이 화면에는 보이지만 DOM에서 숨김 처리된 경우도 현재 보이는 컨트롤만 판별해 한 번 제출합니다. 오늘 반영된 긴 제목·도입 후킹·문장 리듬·병렬 이미지 준비·Google 캡처 검수 단축도 공통 엔진에 포함됩니다.
- 기존 앱 설정 폴더를 찾아 설정을 보존합니다. 설정 저장은 원자적 교체와 마지막 정상본 백업을 사용합니다. 회차 파일과 원고는 실행 자료 폴더에서 확인할 수 있습니다.

패키지는 **ad-hoc 서명**을 검증하며 Developer ID 공증은 포함하지 않습니다. 배포용 Apple 인증서가 필요하므로 공증 완료로 표시하지 않습니다. 설치 도구는 앱 사본의 다운로드 격리 속성만 처리하고 macOS 전체 보안 정책을 변경하지 않습니다. 실제 계정 로그인과 네이버 추가 인증은 사용하는 Mac에서 완료해야 합니다.

## 구성과 개발

| 구성 | 역할 |
| --- | --- |
| `main.js`, `preload.js` | Electron IPC, 웨일 소유권·로그인, 실제 연관어 수집 |
| `blog-runtime.js` | 설정, 수동 실행, 예약, 중지, 자식 프로세스 관리 |
| `backend/engine.py` | JSON-lines 실행 계약, 검색 의도, 회차 복구, 발행 이력 |
| `backend/mac_cli.py` | Mac CLI 탐색, 구독 계정 점검·로그인 |
| `backend/mac_naver.py` | ARM64 드라이버, 웨일 연결, 네이버 인증·편집기 어댑터 |
| `../windows/blog_*.py` | 공통 원고 품질·역할·이미지·이력 엔진 |

Apple Silicon Mac에서 실행합니다. 빌드 도구로 Node 22와 Python 3.12가 필요합니다.

```bash
npm ci
python -m pip install -r backend/requirements-mac.txt
npm test
python -m unittest discover -s tests -p 'test_*.py' -q
bash scripts/build-backend.sh
npm run build:mac
bash scripts/sign-and-verify.sh
```

`.github/workflows/build_mac.yml`은 실제 ARM64 여부 확인 → 테스트 → PyInstaller 엔진 → Electron 앱 → 코드 서명 검증 → 서명된 엔진·앱 실행 → ZIP과 SHA-256 생성 순서로 동작합니다. 계정이 없는 CI에서는 로그인·실제 발행을 수행하지 않습니다. 빌드 결과는 `Blog-M1` Actions 아티팩트이며 기존 공개 릴리스를 덮어쓰지 않습니다.

원고는 현재 기본 문체와 사용자 추가 프롬프트를 사용하고, 8구역·전체 4,000자, 질문형 연결과 과한 키워드 반복 정리를 공통 엔진에서 처리합니다. 이미지 재생성은 탈락한 장만 최대 2회이며, 영어 검색으로 얻은 Google 후보는 사용 조건·글자·로고 검수를 통과해야 블로그 이미지에 추가됩니다.
