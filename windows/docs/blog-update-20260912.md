# Blog 개선 구현 기록

## 이번 수정의 핵심

주제 후보를 비교하는 단계와 확정한 주제를 작성하는 단계를 분리했다. 확정 이후 준비 오류가 발생해도 다음 후보로 바꾸지 않는다. `pending-blog-topic.json`에 주제·연관어·검색 의도·재개 폴더를 저장하고 같은 주제로 최대 3번 준비를 시도한다. 이후에도 다음 예약 실행 또는 앱 재실행에서 같은 주제를 유지한다. 게시 결과가 불확실하면 같은 글을 다시 제출하지 않고 확인 대기로 보존한다.

로또1241 실패 자료에서는 검수 CLI가 `title_intent.related_keywords`에 원래 주제명을 추가한 것이 원인이었다. 주제명만 중복 제거하고 입력에 실제 존재하는 연관어는 유지한다. 입력에 없는 다른 연관어는 자동 승인하지 않고 동일 원고의 형식 수정 요청으로 처리한다. 실제 실패 원고에 이 처리를 적용해 원고 검증 통과를 확인했다.

Antigravity `command` 차단은 셸 권한 전체 허용으로 해결하지 않는다. 확인된 동일 대화를 이어 네이티브 검색·공개 페이지 읽기를 사용하도록 요청한다. 계속 실패하면 단계별 설정에 등록된 다른 CLI로 동일 주제 복구를 요청한다. 근거 없는 검증 승인값을 프로그램이 생성하지 않는다.

## 화면과 설정

- 모든 탭 아래 공용 진행 창: 세로 분할 경계 드래그, 높이 저장·복원, 접기·펼치기, 최대 5000줄.
- 반복 간격: 1~6시간. 다음 회차 예약에 변경값 반영.
- 이미지 개별 작업 버튼 두 개를 통합하고 네이버 로그인 중복 버튼 제거.
- 4단계 각각 CLI·역할·모델 지정. 단계별 모델을 비우면 공급자 기본 모델 사용. 기존 문자열 순서 설정과 객체 단계 설정 호환.
- 프롬프트의 마우스 붙여넣기도 자동 저장 이벤트에 포함. 기본 프롬프트 추가 시 기존 선택 유지.

## 원고 처리

- 작성 / 교차 검수 / 팩트·최신 정보 보강 / 문체 다듬기 역할 분리.
- 팩트 보강은 기존 제목·문단을 유지하고 검증한 정보만 문단 뒤에 추가. 삭제·재작성은 수정 요청 대상.
- 별도 복구 단계에서는 오류가 있는 주장이나 검증 불가능한 수치·날짜를 제거하고 검증 가능한 내용으로 보강한 원고를 다시 검증.
- 문체 단계의 수치·날짜 변경 차단. 실제 제공되지 않은 체험을 꾸며내지 않도록 명시.
- 기본 프롬프트에 다양한 어미, 궁금증을 열고 답을 풀어가는 후킹 규칙 병합. 사용자가 선택한 글쓰기 지침을 앞에 배치.
- 공개 본문에 URL·출처 목록·도구 작성/검수 설명이 있으면 같은 원고 수정 요청. 근거와 변경 설명은 비공개 메타데이터에 유지.

## 검증과 배포

전체 단위·통합 테스트 329개 통과. 실제 로또 실패 JSON 검증 통과. 드래그 높이 복원 및 접기·펼치기는 Tk 위젯 테스트로 확인했다. 실제 공개 발행은 이번 검증에서 실행하지 않았다.

실제 CLI 읽기 진단: Antigravity는 BLS CPI 페이지에 `actually_read=false`를 반환했다. 같은 페이지를 요청한 ChatGPT CLI는 `CPI Home : U.S. Bureau of Labor Statistics`, `actually_read=true`를 반환했다. 따라서 특정 CLI의 읽기 성공을 가정하지 않고 다른 설정된 CLI의 동일 주제 복구를 사용한다.

기존 `dist/Blog.exe`가 실행 중이므로 `build.ps1 -DistPath dist-update`로 업데이트 실행 파일을 별도 생성한다. 기존 앱 종료 후 `dist-update/Blog.exe`를 실행해야 변경 코드가 적용된다. 설정 경로는 동일하다.

선정 사전 점검은 검색 의도·입력 연관어·차단 주제·중복 이력과 설명 가능한 범위를 확인한다. 외부 CLI, 이미지 생성, 네이버의 향후 장애까지 사전 보장할 수는 없으므로 주제 보존 및 재개가 함께 필요하다. 최종 검증을 통과하지 않은 글을 단순히 실패 표시를 없애기 위해 발행하지 않는다.
