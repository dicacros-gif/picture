# 2026-09-13 인터뷰 반영: 선택적 Google 사진 검색 제한

## 확정한 운영 기준

- 글은 독자의 구체적인 궁금증에 답하는지, 내용에 논리적 모순이 있는지, 상투적인 표현이 반복되는지를 중심으로 점검한다.
- 이미지는 본문과 관련되고 장면이 겹치지 않는 사진 6장을 우선한다.
- Google 사진 검색은 글 한 편당 영어 검색어 1개로 한 번만 한다. 실제 썸네일은 최대 8개를 비교하고 가장 적합한 원문은 최대 2개만 연다.
- 검색 실패나 적합한 Google 사진 부족 때문에 원고와 생성 이미지 작업을 기다리게 하지 않는다.

## 검색·캡처 흐름

1. 두 계정이 공유하는 요청 기록을 확인한다. 다른 계정이 Google 검색 중이거나 마지막 요청으로부터 60초가 지나지 않았으면 이번 글의 선택적 Google 작업을 생략한다.
2. 한 검색 결과 화면에서 보이는 썸네일만 캡처한다. 추가 검색·연속 스크롤로 후보를 늘리지 않는다.
3. 실제 썸네일 파일 최대 8개를 한 번의 짧은 CLI 요청에 첨부한다. 주제 관련성, 실사 중심 구성, 적은 글자, 워터마크 부재를 비교해 최대 2개를 고른다. 작은 상품 글자와 회사 로고만으로 탈락시키지 않는다.
4. 선택한 원문만 열어 기존 사용 조건 확인과 사진 캡처를 수행한다. 사용 조건 확인 없이 사용 허가를 추정하지 않는다.
5. 확보한 실제 사진만 한 번 더 워터마크·실사 여부를 확인한다. 썸네일 판정 실패, 원문 확인 실패, 적합한 사진 없음은 추가 검색의 이유가 되지 않는다.
6. CAPTCHA가 나오면 즉시 Google 작업을 끝내고 모든 계정에서 60분간 Google 이미지 검색을 생략한다. 확인창을 자동으로 풀거나 다른 브라우저로 우회하지 않는다.

## 상태 저장과 병렬 실행

`google-image-budget.json`은 계정별 폴더 밖 공통 앱 데이터 폴더에 저장한다. 글별 요청 횟수, 마지막 요청 시각, CAPTCHA 휴식 종료 시각이 재실행 후에도 유지된다. 계정은 짧은 상태 갱신 동안만 잠금을 사용하며 원고 작성·이미지 생성은 이 잠금을 기다리지 않는다.

회차의 `google-search-checkpoint.json`에는 검색 완료와 생략 사유를 남긴다. 같은 원고를 재개하거나 설정을 바꿔도 이미 사용한 검색을 반복하지 않는다. 파일이 바뀐 캡처는 재사용하지 않고 생성 이미지로 진행한다.

## 검증 범위

- 두 계정의 동시 요청 제한, 최소 간격, CAPTCHA 휴식 및 재시작 후 복원
- 글당 한 번 제한, 손상된 기록 또는 저장 실패 시 추가 검색 방지
- 실제 썸네일 첨부·후보 판정·최대 두 원문 선택, CLI 실패 시 링크를 열지 않는 동작
- 원고와 캡처의 병렬 실행, 중지 전파, 브라우저 종료 확인, 회차 재개

현재 CAPTCHA가 보고된 상태에서는 검증을 위해 Google 검색을 반복하지 않는다. 브라우저 동작은 오프라인 회귀 테스트로 검증하고, 다음 허용된 일반 회차에서 실제 사용 결과를 로그로 확인한다.


## 오늘 오류에 대한 원고·이미지 개선

- 형광 강조: 작성 요청과 검사 모두 본문 속 완전한 문장 기준으로 통일한다. 유효하지 않은 강조 지정은 원문을 건드리지 않고 제거하며, 형광 강조가 0개여도 글 작성은 이어간다.
- 출처 보완: 출처 일부의 검증 오류 때문에 사용자 프롬프트와 전체 글을 다시 보내지 않는다. 문제 출처와 관련 주장만 제한된 요청으로 확인하고, 확인하지 못한 사실을 확인된 것으로 바꾸지 않는다.
- 문장 배치: 일반 문장은 2~3문장 묶음을 유지하되 문장 사이 줄바꿈 1회, 묶음 사이 빈 줄 1개를 넣는다. 줄바꿈만 변경된 원고를 내용 변경으로 오인해 재검수하지 않는다.
- 로그인 점검: 같은 회차의 같은 CLI·모델 구성이면 성공한 사전 점검 결과를 재사용한다. 다음 회차·모델 변경·이전 점검 실패에서는 다시 확인하며 실제 CLI 요청의 인증 처리는 유지한다.
- 이미지: 본문이 설명하는 서로 다른 장면 6장을 우선 생성하고 부족하거나 실패했을 때만 예비 이미지로 보충한다. 완료 파일이 바뀌지 않았으면 반복 검사·해시 계산·파일 저장을 생략한다.

## 배포 확인

관련 회귀 테스트 통과 후 Windows Blog.exe를 빌드한다. 기존 프로그램을 정상 종료하고 검증된 파일로 교체한 뒤 저장된 두 계정과 1시간 간격 설정을 유지해 다시 실행한다. CAPTCHA가 이미 보고되었으므로 배포 직후에는 공통 휴식 기록을 먼저 저장하고 Google을 재조회하지 않는다.


## 작업 내용의 네이버 임시저장과 로컬 정리

- 준비를 끝내지 못해도 구조가 확인된 제목과 작성된 본문 1~8구역을 회수해 네이버의 저장 버튼으로 비공개 임시저장한다. 완성하지 않은 구역을 임의로 만들어 넣지 않는다.
- 현재 클릭에 대한 새로운 저장 완료 표시, 계정과 원고 식별자를 확인한 뒤 저장 영수증과 공통 사용 키워드 기록을 먼저 남긴다. 저장한 주제와 사용 연관어는 두 계정 모두 30일 동안 다시 선택하지 않는다. 발행 건수로는 세지 않는다.
- 확인을 마친 회차의 원고·프롬프트·응답·사진과 연결된 임시 폴더를 정리한다. 파일이 사용 중이면 정리 대기열에서 다시 시도한다. 웹 저장 확인이 없으면 로컬 작업물을 보존한다.

- 드롭다운은 청록색 계열의 입력 영역과 화살표 영역으로 구분한다. 펼친 목록도 같은 색상을 사용하며 다크·라이트 전환 즉시 바뀐다.
- 탭, 메뉴, 버튼, 입력 옵션, 펼친 선택 목록까지 굵은 글꼴을 적용한다. 로그의 실패 메시지는 기존 빨간색 표시를 유지한다.
