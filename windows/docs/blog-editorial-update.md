# Blog 화면·원고 품질·후보 점수 개선

## 화면

완료 동작 선택은 상단 바에만 남겼다. 상단 전체 자동화 중지는 자동 재개 취소, 전체 실행 중지 이벤트, 네이버 댓글·발행 작업의 `stop()`을 함께 호출한다. 1번 탭의 Google 이미지 검색 버튼과 3·4번 탭의 중지 버튼을 제거했다. 3번 탭의 자동 선정·원고 준비·네이버 입력 수동 버튼도 제거했다. 자동화에서 사용하는 메서드는 유지했다. 3번 탭 하단에는 실행 자료 폴더, 결과 복사, 웨일 네이버 로그인만 남는다.

## 작성과 검사

작성 스키마에 `bridge_sentences`와 `subheading_keywords` 배열을 추가했다. 도입부의 검색 의도와 답할 순서, 중간 구역의 앞뒤 연결, 마지막 실행 정리를 지시한다. 8구역 각각 650자 이상, 최소 4구역의 확인된 금액·기간·횟수·조건, 문장형 절차와 비교를 요청한다. 650자 × 8구역이므로 구역 조건을 모두 만족하면 전체는 최소 5200자다.

제목과 서로 다른 소제목 연관어를 검사한다. 작성용 연관어는 CLI가 선택한 우선 연관어 뒤에 실제 수집된 나머지를 유지한다. 강화 검사를 사용하는 새 자동화 후보는 실제 연관어가 8개 이상 있는 후보를 선정 전에 검토한다. 입력에 없는 연관어를 만들어 내지 않는다.

주제어 밀도는 원래 핵심 검색어 출현 횟수 / 본문 공백 단위 어절 수 × 100으로 계산하며 목표는 2~3%다. 긴 글 주제 문장 전체를 반복시키지 않도록 원래 검색어를 밀도 기준으로 전달한다.

`blog_quality.py`는 길이, 구역 수, 금지 표현, 세 문장 연속 어미, 도구의 작성·검수 설명, URL·출처·참고 자료, 숫자 인덱스·표, 구역 간 문장 중복, 소제목 키워드 중복, 연결 문장 누락, 구체적 정보 수, 주제어 밀도를 검사한다. 문장 중복은 문장 유사도 90% 이상인 문장이 해당 구역 문장의 60% 이상인 경우다.

## 자동 수정과 발행 진행

문체 역할 CLI(없으면 마지막 단계)에 지적한 부분을 최대 두 번 수정 요청한다. 응답은 구역 번호와 정확한 기존 문자열/교체 문자열로 받고, 지적되지 않은 구역의 수정이나 검증 승인값 교체는 허용하지 않는다. 변경 결과를 다시 검사한다.

이후 코드는 공개 출처·도구 설명 문장 삭제, 안전하게 변환 가능한 어미 교체, 금지 연결어·숫자 인덱스 제거를 처리한다. 길이 보강은 이미 검증된 1차 자료의 미사용 근거 중 해당 소제목에 관련된 내용만 사용한다. 숫자와 경험을 창작하거나 반복 문장으로 분량을 채우지 않는다.

남는 편집 목표는 `editorial_followup`으로 실제 미달 항목을 기록하고 같은 원고로 진행한다. 목표를 모두 통과한 것처럼 표시하지 않는다. 기존의 사실·출처 승인과 네이버 입력에 필요한 기본 형식 검증은 유지한다. 원고를 변경한 경우 최종 사실 검수를 다시 받는다. 모든 검사·수정 내역은 진행 창과 회차 폴더의 `editorial-quality.json`에 남는다.

팩트 단계는 기존 구역을 통째로 재작성할 수 없다. 다만 확인되지 않은 수치·조건 문장을 확인된 정보로 교체하는 부분 수정은 `fact_corrections`에 원문·교체문·이유·검증된 근거 URL을 기록한 경우 허용한다.

## 연관어 점수

기존 최대 12개 × 2점에서 최대 30개 × 4점으로 가산점을 높였다. 의미가 연결되는 중복 없는 연관어만 센다. 여러 소스 동시 등장 가중치는 유지한다. 표시 점수 100점에 도달한 후보끼리도 원점수와 연관어 수로 순서를 구분한다. 점수 근거 로그에 연관어 수와 가산점을 표시한다.

## 배포

업데이트 실행 파일: `dist-update/Blog.exe`. 기존 앱을 종료하고 업데이트 파일을 실행한다. 같은 앱 데이터 경로를 사용하므로 저장된 설정과 프롬프트는 유지된다. 이번 검증에서는 공개 블로그 발행을 실행하지 않는다.
