# 브라우저별 계정과 시간당 발행 개선

## 계정 설정

3번 탭에 계정 두 개를 설정한다. 첫 계정은 웨일·에지·크롬, 추가 계정은 에지·크롬을 선택할 수 있다. 각 계정의 블로그 ID를 입력하고 추가 계정의 `사용`을 켜면 하단 진행 창이 두 칸으로 나뉜다. 설정과 프롬프트는 자동 저장된다. 계정·브라우저 변경은 자동화를 중지한 뒤 다시 시작할 때 적용한다. 글쓰기 프롬프트·역할·모델은 이미 시작한 글의 설정을 보존하고 다음 새 글부터 적용한다.

추가 계정은 `이 계정 로그인`으로 연 전용 프로필에서 한 번 로그인해야 한다. 일반 Edge·Chrome의 로그인 데이터는 복사하지 않는다. 새 브라우저는 로그인된 사용자의 내 블로그 ID와 글쓰기 대상 ID를 대조한 뒤 입력한다. 같은 블로그 ID를 두 계정에 지정할 수 없다.

실시간 검색어는 공통 수집기가 한 번 가져온다. 계정별 원고·이미지·준비 상태·브라우저 영수증은 별도 폴더에 둔다. 글과 이미지 작업은 계정별로 병행하며 네이버 입력·발행은 공통 잠금으로 한 계정씩 처리한다. 기존 웨일 계정의 작업 폴더와 미완료 원고는 유지한다.

## 시간 예산과 진행

계정마다 회차 시작부터 50분의 같은 시간 예산을 사용한다. 같은 계정의 다음 회차를 중첩해 같은 편집기나 준비 상태를 덮어쓰지 않는다. 서로 다른 계정은 독립적으로 진행한다. 1~6시간 예약 간격을 유지하며 대기 중 간격을 바꾸면 다음 예약에 반영한다.

초고가 검증되면 이미지 생성을 후속 원고 검수와 병행한다. 이미지 제공자 두 개가 동시에 처리하며 완료된 파일부터 실제 시각 검수를 받는다. 우선 여섯 장을 준비하고 표지를 포함한 서로 다른 여섯 장이 통과하면 남은 선택 작업을 종료한다. 부족할 때만 추가 후보를 준비한다. 시간당 모드의 재생성은 이미지당 한 번(최초 포함 최대 두 번)이다. Google 사진은 별도 검수·사용 조건 확인을 통과하면 추가할 수 있다.

작성 응답 제한은 600초, 검수·보완은 기본 300초, 이미지 검수는 120초다. 실제로 검수하지 않은 원고나 이미지를 승인 처리하지 않는다. 외부 CLI의 제한, 로그인 실패, 네이버 서비스 장애가 발생하면 발행 완료를 보장할 수 없다. 완료 단계와 미제출 자료는 보존하고 원인을 기록한다. 두 회차 연속 진전이 없고 제출 기록이 없는 원고는 보관한 뒤 새 주제를 선택한다. 불확실한 제출 영수증은 자동 재발행하지 않는다.

계정별 `cycle-results.jsonl`에 시간·결과·URL을 기록하고 하단 창에 당일 예약 횟수·실제 발행 횟수·발행률을 표시한다.

## 중복과 정리

공통 `published-topic-history.json`에서 최근 30일 동안 어느 브라우저에서든 사용한 주제·연관어를 제외한다. `writer-topic-reservations.json`의 원자적 예약으로 작성 중인 다른 계정의 키워드도 제외한다. 만료된 발행 기록은 삭제하지 않고 과거 기록으로 남긴다. 불확실한 제출은 날짜와 무관하게 보존한다. 손상된 이력을 추측으로 복구하거나 무시하지 않는다.

확인된 발행 영수증과 공통 이력이 일치하는 회차만 정리 대기열에 넣는다. 파일 공유 잠금으로 실패하면 다음 회차에 재시도한다. 차단된 삭제, 변경된 원고, 미발행·실패 자료는 보존한다. 오래됐다는 이유만으로 글쓰기 회차 폴더를 삭제하지 않는다.

## 제목과 사진 문구

첫 제목은 첫 훅과 마지막 SEO 제목의 핵심 설명을 연결하고 실제 연관어를 포함한다. 40~65자를 권장하되 같은 연도·주제어를 반복하거나 글자 수를 채우려고 내용을 만들지 않는다. 제목만 수정할 때는 본문과 이미지 문맥을 보존하고 다시 검수한다.

첫 사진은 얼굴 없는 실사 배경, 주변 아웃포커싱, 중앙의 검정 반투명 패널을 사용한다. 문구는 자연스러운 띄어쓰기와 `?`로 끝나는 질문이며 공백 포함 최대 28자다. 굵은 고딕체의 흰색·형광 녹색과 그림자를 사용한다. Google 사진도 영어로 검색한 원사진의 균일한 바깥 여백만 정리한 뒤 같은 방식으로 문구를 표시한다. 원본 글자·로고·워터마크를 지우기 위한 자르기는 하지 않는다.

## 확인 결과

기존 발행 URL `https://blog.naver.com/macdcross/224409924187`의 제목·8구역 본문·사진 6장과 실제 업로드 파일 일치를 확인했다. 이는 이번 계정 확장 이전의 발행이며 새 이중 계정 회차 성공으로 계산하지 않는다.

새 Edge 152.0.4191.66과 Chrome 152.0.7977.84는 각각 별도 QA 프로필에서 공식 드라이버로 `about:blank` 연결 및 정상 종료를 확인했다. 추가 계정의 실제 발행에는 사용자의 블로그 ID 지정과 전용 창 로그인이 필요하다.
