# Blog 실행 로그 기반 개선

2026-09-13 사용자가 실행 로그를 확인하며 오류와 개선점을 수정하도록 요청했다. 실제 실행 중인 1시간 자동 발행 회차를 관찰하고, 사용자 설정과 승인 기록을 유지하며 수정했다.

## 실제 관찰

- 회차 `20260913-011046-09e5f59f`는 미국 8월 CPI 주제로 시작했다.
- 첫 원고는 8구역·5,417자로 기본 검사를 통과했다.
- Antigravity의 팩트 추가 결과는 기존 본문이나 수치를 바꾸지 않았지만, 추가 문장 앞의 빈 줄 차이 때문에 원문 변경으로 판정됐다. 그 결과 불필요한 형식 재요청과 복구 요청이 이어졌다.
- 구글 검색 `Korean investor checking inflation data`는 아이콘을 포함한 요소 2개를 준비 완료로 판단한 뒤 사진 미리보기 시간 초과로 끝났다.
- 화면 로그는 파일로 저장되지 않아 종료 후 당시 상황을 확인하기 어려웠다.
- CLI 요청이 시작됐는데도 미완료 회차에는 아직 원고 폴더 경로가 없었다. 강제 종료 시 승인된 작업을 잃을 수 있는 구간이었다.
- 현재 저장된 마지막 CLI 역할은 팩트 보강이다. 기계 검사가 통과하면 자연스러운 문체 다듬기가 생략될 수 있었다.

## 실제 브라우저 확인

사용 중인 웨일과 별도의 데이터 폴더로 같은 실패 검색어를 한 번 검사했다. 11.43초 후 사진 미리보기가 정상적으로 열려 원문 검사까지 도달했다. 다만 유일한 결과가 출처 표시 의무가 있는 지도(CC BY 3.0)였으므로 사용하지 않았다. 이 검색에서는 미리보기가 열렸지만 다른 검색어까지 정상이라고 일반화할 수는 없다.

01:27 이후 실제 회차의 다른 검색어에서는 미리보기 시간 초과가 반복됐다. 개별 후보의 재시도만 제한하면 전체 후보 수만큼 오래 대기하는 문제를 발견해 연속 실패 및 시간 상한을 추가했다. 정상 중지 로그와 기존 회차 저장을 확인한 뒤 다시 빌드했다.

검증 자료는 `qa-live-monitor-20260913/google-smoke/`에 보존했다. 시험용 브라우저는 종료했으며 실제 작성 중인 브라우저에는 연결하지 않았다.

추가로 별도 프로필에서 `economic calendar on desk photo`를 약 22초 동안 조사했다. 첫 결과의 활성 사진은 원본 2121×1414, 화면 559×373으로 정상 표시됐고 JS 클릭과 상위 버튼 클릭 모두 같았다. 기존 앱 프로필에서만 보인 숨김 상태는 재현되지 않았다. 따라서 클릭 방식을 바꿔 해결됐다고 단정하지 않고, 재사용 가능한 사진 여부와 별개인 이 관찰을 `qa-live-monitor-20260913/google-preview-diag/preview-result.json`에 남겼다. 다음 점검에서도 표시 문제는 관찰 대상으로 유지한다.

## 후속 점검

이 작업에 `Blog 실행 로그 점검`을 15분 간격으로 설정했다. 새로운 오류·검증된 수정·발행 완료·사용자 조치가 필요한 경우만 알린다. 진행 중인 CLI 요청이나 정상적인 예약 대기를 실패로 단정하지 않고, 재시작이 필요하면 기존 회차와 제출 상태를 먼저 보존한다.

## 최종 사실 검수의 원고 보존과 부분 수정

05:33 공휴일 회차의 최종 사실 검수에서 실제 지적이 나왔다. 기존 복구는 이 지적을 작성 지침 `revision_feedback`에 추가해 1~3단계 체크포인트를 모두 무효화했다. 이후 팩트 추가 장부와 원문이 일치하지 않는 응답이 반복되어 불필요한 재작성 시간이 늘어났다.

- 새 `final_review_feedback`은 최종 편집 원고의 보완 지침으로만 사용한다. 기존 회차에 이미 저장된 `revision_feedback`은 그대로 두어 완료한 단계의 지문을 유지한다.
- 최종 검수 직전에 미승인 편집본을 `editorial.pending.json`에 보존한다. 재실행 시 요청·원고·문체 기록·검수 경로 지문을 확인하고 그 원고의 검수부터 재개한다.
- 실제 사실 지적은 기존 팩트 변경 장부와 1차 자료 확인 기준에 따라 최대 2회 부분 수정한다. 요청 시작 전에 횟수를 저장해 실패·취소·재실행이 한도를 초기화하지 않는다.
- 의미적인 거절 이후에는 지적한 CLI와 모델을 고정한다. 수정된 원고는 같은 검수 경로에서 새 승인을 받아야 한다.
- `issues: null`처럼 검수 JSON 형식이 잘못된 경우에는 같은 CLI와 모델에 검수만 재요청한다. 사실 수정 횟수는 소비하지 않는다.
- 팩트 오류 로그에는 `fact_corrections`, `fact_additions`, `paragraphs`의 실제 배열 위치와 출처 연결 문제를 표시한다. 인증값이 포함될 수 있는 URL 부분은 가린다.
- 텍스트 요청은 제공된 원고와 공개 웹 자료만 사용하도록 범위를 명시한다. 실제 실패 원인인 앱 데이터 폴더 탐색에는 권한을 추가하지 않는다. 이미지 검수는 명시적으로 첨부한 이미지 읽기를 유지한다.

이 복구는 이미지 생성 전 최종 편집·사실 검수 경로에 적용한다. 이미지 준비 이후 별도 감사 모드는 원고 변경 시 이미지 문맥도 재검수해야 하므로 기존 복구 경로를 유지한다. 수정판은 별도 폴더에 빌드하고 실행 중인 EXE를 덮어쓰지 않는다.

관련 통합 시험 278개가 통과했으며, 검수 JSON 형식 오류와 오류 처리 경로의 마지막 보강 후 관련 40개도 다시 통과했다. 검수 원고 변조 차단, 1~3단계 체크포인트 바이트 보존, 이미지 준비 실패 후 편집본 재사용, 동일 검수자 재확인, 누적 수정 한도 및 취소 시 보존을 포함한다.

06:04의 문체 실패는 같은 `70일`을 후킹 문장에서 한 번 더 언급해 수치 출현 횟수가 달라진 경우였다. 숫자 검사는 완화하지 않고 해당 교체만 원문으로 유지하며 나머지 유효한 교체는 적용하도록 변경했다. 강조·연결 문구도 실제 수락된 본문에 존재하는 값만 유지한다. 실제 저장 응답의 8개 교체 중 7개를 수락했고 원고 형식 검사를 통과했다.

원래 단계 체크포인트와 원시 응답, 편집 입력·출력, 문체 입력의 지문을 대조해 이 회차의 미승인 편집본을 복구하는 일회성 QA 절차를 준비했다. 격리 복사본에서 세 작성 체크포인트를 그대로 재사용하고 추가 작성·문체 CLI 호출 없이 새 사실 감사 입구까지 도달함을 확인했다. 복구본은 최종 승인이 없는 `awaiting_audit` 상태이며, 앱이 실제 최종 검수를 수행해야 이미지 준비와 발행을 진행한다.
